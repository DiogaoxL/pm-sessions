| 2026-07-18 | Implementação de TimeSlotRepository (Task 03)      | Injeção do cliente do Supabase via construtor e aplicação de filtros DR-008 | Permite reutilizar conexões e desacopla a classe de factories estáticas globais. Aplica regras de expiração (corte) e ordenação temporal diretamente na query SQL do Supabase. | Retorno estritamente ordenado por data e hora crescentes, filtrando slots passados sob fuso `America/Sao_Paulo`. |
| 2026-07-18 | Implementação de Concorrência (Task 04)            | Optimistic Lock no `SessionRepository` via comparação de valor lido         | Garantir atomicidade da reserva sem depender de RPCs ou migrações de funções Postgres complexas, controlando tudo na aplicação via PostgREST.                                  | Update falha se o número de participantes mudar entre a leitura e escrita, impedindo overbooking.                |
