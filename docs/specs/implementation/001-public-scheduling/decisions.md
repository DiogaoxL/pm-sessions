# Decisions — 001 Public Scheduling

| Data       | Contexto                                           | Decisão                                                                      | Motivo                                                                                                                                                                         | Impacto                                                                                                          |
| ---------- | -------------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| 2026-07-18 | Concorrência de reservas simultâneas no mesmo slot | Usar update condicional seguro (`AND current_participants < capacity`)       | Evitar overbooking de forma atômica no banco sem lock pessimista pesado                                                                                                        | Bloqueia submits de candidatos quando a vaga esgota na fração de segundo anterior                                |
| 2026-07-18 | Contratos de persistência (Task 02)                | Adoção definitiva do Repository Pattern e Dependency Inversion               | Desacoplar serviços de negócio da dependência direta de APIs proprietárias do Supabase SDK                                                                                     | Facilidade de testes de unidade com mocks e manutenibilidade futura do banco                                     |
| 2026-07-18 | Definição de Tipos e DTOs (Task 02)                | Tipagens de interfaces derivadas estaticamente das tabelas físicas do banco  | Garantir que o TypeScript detecte erros estruturais de banco em tempo de compilação                                                                                            | Evita incompatibilidades de tipagem em produção                                                                  |
| 2026-07-18 | Implementação de TimeSlotRepository (Task 03)      | Injeção do cliente do Supabase via construtor e aplicação de filtros DR-008  | Permite reutilizar conexões e desacopla a classe de factories estáticas globais. Aplica regras de expiração (corte) e ordenação temporal diretamente na query SQL do Supabase. | Retorno estritamente ordenado por data e hora crescentes, filtrando slots passados sob fuso `America/Sao_Paulo`. |
| 2026-07-18 | Implementação de Concorrência (Task 04)            | Optimistic Lock no `SessionRepository` via comparação de valor lido          | Garantir atomicidade da reserva sem depender de RPCs ou migrações de funções Postgres complexas, controlando tudo na aplicação via PostgREST.                                  | Update falha se o número de participantes mudar entre a leitura e escrita, impedindo overbooking.                |
| 2026-07-18 | Junção em Duplicidade de Candidatos (Task 05)      | Uso de `sessions!inner(time_slot_id)` no `ParticipantRepository`             | Evitar downloads desnecessários de dados de sessões no runtime do Node.js, empurrando o filtro correlacionado para ser resolvido nativamente no PostgreSQL pelo PostgREST.     | Consulta de duplicados rápida, performática e tipada. Repositório mantido sem lógica de negócio ou Services.     |
| 2026-07-19 | Framework de Testes Automatizados (Task 05A)       | Adoção do Vitest rodando em ambiente Node configurado via `vitest.config.ts` | Oferece execução de testes extremamente rápida, suporte nativo a ESM e TypeScript, e facilidade de integração com aliases de importação do Next.js.                            | Execução de testes de repositórios e serviços no backend sem necessidade de build completo do Next.js.           |
| 2026-07-20 | Rota pública de agendamento (RC-4.1 Task 01)       | Criação da rota `/scheduling` exposta em `page.tsx` no App Router.           | Centralizar a interface do agendamento público em uma rota navegável, integrando os componentes visualmente.                                                                   | A interface torna-se acessível via URL, atendendo à Definition of Done visual do projeto.                        |
| 2026-07-20 | Ação getSessionBySlotAction (RC-4.1 Task 01)       | Criação de Server Action que resolve a sessionId correspondente ao slot.     | O SchedulingForm depende de sessionId (que o card de slot não contém nativamente). Resolvido via service no server-side.                                                       | O formulário de agendamento é carregado de forma limpa e transparente após a seleção do slot.                    |
| 2026-07-20 | UX Móvel responsiva (RC-4.1 Task 01)               | Apresentar formulário em Bottom Sheet com bloqueio de scroll no Mobile.      | Evita que o usuário móvel tenha de rolar a listagem de horários inteira para encontrar os campos do formulário.                                                                | Experiência e usabilidade em telas pequenas drasticamente aprimorada sem duplicar código.                        |
| 2026-07-20 | UX de Erros de Form (RC-4.1 Task 02)               | Separação entre erros estruturais (Zod) e erros de negócio (Banner global).  | Apresentar mensagens inline para erros Zod e manter banner global apenas para erros de negócio, reduzindo ruído visual e melhorando acessibilidade.                            | Layout do formulário limpo sob falhas de validação, com erros de negócio claramente identificados.               |
