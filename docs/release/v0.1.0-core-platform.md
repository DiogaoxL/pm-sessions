# Release Notes: v0.1.0-core-platform

> Release readiness and validation log for the Core Platform (Sprint 1 Foundations).

---

## 1. Overview

Version `v0.1.0-core-platform` establishes the complete, production-ready foundation for the PM Sessions application, establishing repository architecture, database schemas, API authentication, and security configurations.

---

## 2. Foundations Implemented

### Foundation 001: Project Setup (Bootstrap)

- Monorepo structure using `pnpm`.
- Next.js 16 (App Router) + Tailwind CSS v4 + shadcn/ui.
- Strict quality gates (Husky, Prettier, ESLint, Commitlint).

### Foundation 002: Supabase Persistence

- Database initial schema migrations (`admins`, `time_slots`, `sessions`, `participants`).
- Supabase Server, Browser, and Admin client configurations.
- Schema TypeScript types generated.

### Foundation 003: Google Cloud Integration

- Google Cloud Console OAuth Consent Configuration.
- Enable API permissions (Google Calendar, People API).

### Foundation 004: Authentication & Security

- Next.js 16 SSR Cookie authentication using `@supabase/ssr`.
- Secure Route Groups (`(auth)` and `(admin)`) layout structure.
- Canonical GET `/logout` endpoint and state clearance.
- Row Level Security (RLS) policies configured and optimized with indexes.
- Hardened callback route with try-catch logic and structured auditing logs.

---

## 3. Pre-Release Validation Log

### Automated Verifications

- **Linter**: `pnpm --filter web lint` -> **✅ Passed**
- **Type Checking**: `pnpm --filter web typecheck` -> **✅ Passed**
- **Production Build**: `pnpm --filter web build` -> **✅ Passed**

### Manual Testing Scenarios Covered

1. **Primeiro login autorizado**: Linking verified and `auth_user_id` successfully saved.
2. **Segundo login**: Reused existing session and `auth_user_id` correctly.
3. **Login de usuário não cadastrado**: Session rejected and redirected to `/login?error=unauthorized`.
4. **Logout**: Cookie cleared and user redirected to `/login`.
5. **Acesso direto sem login**: Intercepted by middleware and redirected to `/login`.
6. **Acesso a login já autenticado**: Intercepted by middleware and redirected to `/admin/dashboard`.
7. **Simulação de erro**: Handled by callback catch block and redirected to `/login?error=server`.
